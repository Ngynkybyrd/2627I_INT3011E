\section{\lang{Thuật toán và triển khai adapter}{Algorithm and adapter implementation}}
\label{sec:workflow}
\lang{Giả mã dưới đây tóm tắt luồng đã triển khai bằng parser, model builder, solver adapter, decoder và checker riêng. Các công thức ở phần trước là đặc tả mô hình; source code thực nằm trong repository. Giả mã không thay cho runner có hard process guard và không chứng minh một đợt benchmark đã chạy.}{The pseudocode below summarizes the implemented parser, model builder, solver adapter, decoder, and separate checker. Earlier equations specify the models; the actual source code belongs in the repository. This workflow does not replace a runner with a hard process guard or establish that a benchmark has run.}

\textbf{\lang{Giả mã: giải một input}{Pseudocode: solve one input}}
\begin{enumerate}
 \item \lang{Đọc/parse input thành Puzzle; lỗi cấu trúc, JSON hoặc file trả INVALID\_INPUT. Kiểm method/encoding/budget theo API trước khi dựng mô hình.}{Read/parse the input into a Puzzle; structural, JSON, or file errors produce INVALID\_INPUT. Check method/encoding/budget against the API before building.}
 \item \lang{Chuẩn bị thư viện backend ngoài phần đo; runtime thiếu được báo UNAVAILABLE.}{Prepare backend libraries outside measurement; report missing runtime as UNAVAILABLE.}
 \item \lang{Bắt đầu đồng hồ đơn điệu $t_0$; lấy deadline sớm hơn giữa $t_0+$cutoff và deadline caller (nếu có). Nếu hết ngân sách thì TIMEOUT.}{Start the monotonic clock at $t_0$; use the earlier of $t_0+$cutoff and any caller deadline. If the budget is exhausted, return TIMEOUT.}
 \item \lang{Dựng CNF hoặc model CP/ILP và tạo/nạp solver mới. Tính phần build/setup; nếu đã hết ngân sách thì bỏ qua solve và trả TIMEOUT.}{Build the CNF or CP/ILP model and create/load a fresh solver. Account for build/setup; if the budget is exhausted, skip solving and return TIMEOUT.}
 \item \lang{Gọi solver với ngân sách còn lại, dùng giới hạn native và cơ chế ngắt hợp tác được API hỗ trợ. Giữ raw status.}{Call the solver with the remaining budget, using supported native limits and cooperative interruption. Retain the raw status.}
 \item \lang{Chốt thời điểm kết thúc native solve và các thời gian đã đo. Kết quả đến muộn thành TIMEOUT; không nhận incumbent đến muộn.}{Record native-solve completion and observed component times. Late results become TIMEOUT; do not admit a late incumbent.}
 \item \lang{Nếu chứng minh không khả thi, trả UNSAT. Nếu không có candidate hợp lệ, phân loại TIMEOUT, ERROR hoặc LICENSE\_LIMIT theo bằng chứng; không biến unknown thành UNSAT.}{Return UNSAT only on proved infeasibility. With no acceptable candidate, classify TIMEOUT, ERROR, or LICENSE\_LIMIT from evidence; do not turn unknown into UNSAT.}
 \item \lang{Giải mã candidate thành bảng đầy đủ; lỗi decode là ERROR. SAT chỉ giải mã biến chính; MIP phải qua kiểm tính hữu hạn/nguyên trước khi chọn giá trị.}{Decode the candidate into a complete grid; decoding failure is ERROR. SAT decodes primary variables only; MIP values must pass finite/integrality checks before selection.}
 \item \lang{Chạy checker độc lập kiểm miền, hàng, cột, khối và clues. Chỉ trả SAT kèm nghiệm nếu checker chấp nhận; từ chối hoặc lỗi checker là ERROR.}{Run the independent checker on domains, rows, columns, blocks, and clues. Publish SAT with a solution only if accepted; rejection or checker failure is ERROR.}
 \item \lang{Trên mọi đường thoát, dừng/join timer trước khi hủy native solver và dọn tài nguyên. Lỗi cleanup được báo rõ; không công bố nghiệm thành công khi cleanup lỗi.}{On every exit path, cancel/join timers before native solver deletion and release resources. Report cleanup failure explicitly rather than publishing a successful solution.}
\end{enumerate}

\subsection{\lang{Cách gọi thư viện và kiểm nghiệm}{Library use and validation}}
\lang{Backend SAT là \texttt{pysat.solvers.Glucose3} trong python-sat 1.9.dev16~\cite{pysat2018,glucose2009,minisat2004}. Năm đối chứng dùng OR-Tools CP-SAT~\cite{cp-sat-doc}, gurobipy~\cite{gurobi-manual}, CPLEX Python API trực tiếp (\texttt{cplex.Cplex}, không dùng DOcplex.MP)~\cite{cplex-python-api}, DOcplex.CP cho CP Optimizer~\cite{cplex-cp-doc}, và highspy cho HiGHS~\cite{highs-python,highs2018}. SciPy chỉ cung cấp ma trận sparse cho ILP trong các adapter này, không phải backend solve HiGHS qua \texttt{scipy.optimize.milp}.}{The SAT backend is \texttt{pysat.solvers.Glucose3} in python-sat 1.9.dev16~\cite{pysat2018,glucose2009,minisat2004}. The five baselines use OR-Tools CP-SAT~\cite{cp-sat-doc}, gurobipy~\cite{gurobi-manual}, the direct CPLEX Python API (\texttt{cplex.Cplex}, without DOcplex.MP)~\cite{cplex-python-api}, DOcplex.CP for CP Optimizer~\cite{cplex-cp-doc}, and highspy for HiGHS~\cite{highs-python,highs2018}. In these adapters SciPy supplies sparse ILP matrices; it is not a HiGHS solve backend through \texttt{scipy.optimize.milp}.}
\lang{Phía SAT, API công khai là \texttt{prepare\_backend} và \texttt{solve\_sat}; mỗi lượt dùng Glucose3 mới. Adapter gọi CNF builder với encoding đã chọn, dùng native solve có hỗ trợ interrupt, rồi chuyển model qua decoder và \texttt{validation.check\_solution}. Decoder không suy giá trị ô từ biến phụ.}{For SAT, the public API consists of \texttt{prepare\_backend} and \texttt{solve\_sat}; each call uses a fresh Glucose3 instance. The adapter calls the CNF builder with the selected encoding, uses interrupt-capable native solving, then passes the model through decoding and \texttt{validation.check\_solution}. Auxiliary variables do not determine decoded cell values.}

\lang{Phía đối chứng, \texttt{solve\_baseline} nhận một trong các method \texttt{cpsat}, \texttt{gurobi}, \texttt{cplex\_mip}, \texttt{cpoptimizer}, \texttt{highs}. CP-SAT/CP Optimizer dùng builder CP; Gurobi/CPLEX MIP/HiGHS nhận cùng ma trận ILP, bounds, integrality và objective hằng. Mỗi lượt có đối tượng mới và một luồng/worker. Các adapter giữ raw status và dùng cùng checker production.}{For comparisons, \texttt{solve\_baseline} accepts one of \texttt{cpsat}, \texttt{gurobi}, \texttt{cplex\_mip}, \texttt{cpoptimizer}, or \texttt{highs}. CP-SAT/CP Optimizer use the CP builders; Gurobi/CPLEX MIP/HiGHS consume the same ILP matrix, bounds, integrality, and constant objective. Each call has fresh objects and one thread/worker. Adapters retain raw statuses and use the same production checker.}

\lang{MIP chỉ chấp nhận giá trị hữu hạn cách 0 hoặc 1 không quá $10^{-6}$, với đúng một giá trị được chọn mỗi ô; không làm tròn tùy ý một nghiệm phân số. HiGHS còn phải báo primal feasibility/integrality phù hợp trước decode. Một incumbent trong lượt time-limit chỉ có thể thành SAT nếu đến đúng hạn và checker chấp nhận. UNSAT cần bằng chứng infeasibility; thiếu runtime, vượt license và unknown được phân biệt.}{MIP decoding accepts only finite values within $10^{-6}$ of 0 or 1, with exactly one selected value per cell; arbitrary rounding of fractional solutions is not allowed. HiGHS must also report acceptable primal feasibility/integrality before decoding. A time-limit incumbent can become SAT only if it arrived on time and passes checking. UNSAT requires infeasibility evidence; missing runtime, license limits, and unknown outcomes remain distinct.}

\subsection{\lang{Ranh giới thời gian và bảo vệ tiến trình}{Timing boundary and process safeguards}}
\lang{Imports/đọc input nằm ngoài phần đo. Build gồm dựng mô hình/CNF, tạo và nạp solver; solve dùng phần ngân sách còn lại. Decode, checker và cleanup nằm ngoài build+solve. Việc nhận nghiệm theo deadline dựa vào thời điểm native solve kết thúc, không dùng thời điểm checker hoàn tất để tính thời gian solve. Các thành phần thời gian không biết sau khi bị dừng cưỡng bức phải để thiếu, không bịa số.}{Imports/input reading precede measurement. Build includes model/CNF construction and solver creation/loading; solving uses the remaining budget. Decoding, checking, and cleanup are outside build+solve. Deadline admission uses native-solve completion, not checker completion as the solve endpoint. Timing components unknown after forced termination must remain missing rather than invented.}

\lang{Ngắt native của SAT và timer/giới hạn native của baseline là hợp tác. Riêng DOcplex 2.32.264, TimeLimit nằm trong CPO đã gửi, nên không hứa chỉnh chính xác native TimeLimit sau load: adapter dùng preload để tính build, timer gọi abort\_search theo deadline thực và từ chối kết quả muộn. Preload hook riêng cần kiểm lại khi nâng DOcplex. Nếu timer join thất bại, adapter báo ERROR và có thể hoãn hủy native để tránh callback vào bộ nhớ đã giải phóng.}{SAT native interruption and baseline timers/native limits are cooperative. In DOcplex 2.32.264, TimeLimit is embedded in transmitted CPO, so an exact post-load native TimeLimit is not promised: the adapter uses preload for build accounting, an abort\_search timer against the actual deadline, and late-result rejection. The private preload hook needs rechecking on DOcplex upgrades. If timer joining fails, the adapter reports ERROR and may defer native deletion to avoid a callback into released memory.}

\lang{Measurement-end hook và hard worker/process-tree guard đã được nghiệm thu. Runner dùng START/END để áp cutoff đúng phần đo, rồi chuyển sang watchdog hậu xử lý và dọn process tree khi cần. Pilot đã kiểm đường tích hợp này; native timeout riêng vẫn là hợp tác. Mục~\ref{sec:setup} mô tả cấu hình đợt chính đã khóa; Mục~\ref{sec:results} báo kết quả thực chạy, tách khỏi pilot.}{The measurement-end hook and hard worker/process-tree guard are accepted. The runner uses START/END to apply the cutoff to measurement, then switches to a postprocessing watchdog and process-tree cleanup as needed. The pilot exercised this integration; native timeout alone remains cooperative. Section~\ref{sec:setup} describes the frozen main configuration; Section~\ref{sec:results} reports its executed results separately from the pilot.}
